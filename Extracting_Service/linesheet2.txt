TASK:
Extract product data from the document.

GOAL:
For each product_name, collect ALL available attributes that appear
DIRECTLY BELOW that product_name in the document.

From the header or footer collect 
-merchants name 
-the order number
-delivery date 

IMPORTANT SCOPE RULE:
Only collect attributes that are physically located directly below
the product_name in the source text.
Do NOT infer, guess, or copy attributes from other products.
If an attribute is not present directly below the product_name, set it to null.

────────────────────────────────────────
IMAGE + LAYOUT AWARENESS (ADDITIVE LOGIC)
────────────────────────────────────────

DOCUMENT STRUCTURE ASSUMPTION:
The document may contain images with bounding boxes, and text blocks
with bounding boxes.

IMAGE–PRODUCT ASSOCIATION RULES:
- A product_name MAY have an image directly ABOVE it.
- The associated image is the nearest image whose bounding box:
  a) is vertically ABOVE the product_name bounding box, AND
  b) has significant horizontal overlap with the product_name
     (at least 30% overlap of width), AND
  c) has the smallest vertical gap to the product_name among candidates.
- If no such image exists, image fields MUST be null.

DESCRIPTION ABOVE IMAGE (LIMITED EXCEPTION):
- Some product description text MAY appear directly ABOVE the associated image.
- If present, capture ONLY the nearest contiguous text block(s) immediately
  above the image that:
  a) overlap horizontally with the image, AND
  b) are closer to the image than any other product_name, AND
  c) clearly describe the same product.
- This text may be assigned ONLY to the `description` field.
- This exception applies ONLY to description text.
- ALL other attributes must still obey the "directly below product_name" rule.

BOUNDING BOX RULES:
- Preserve the exact bounding box of the associated image.
- Preserve the exact bounding box of the product_name text.
- Do NOT infer or approximate bounding boxes.

────────────────────────────────────────
PRODUCT NAME RULES (STRICT):
────────────────────────────────────────

- Extract product names exactly as they appear.
- A product_name MAY span multiple consecutive lines.
- If a product name continues onto the next line, concatenate those lines
  in order and treat them as ONE product_name string.
- Preserve internal line breaks using "\n".
- Do NOT modify wording, punctuation, capitalization, or parentheses.
- Only trim leading and trailing whitespace from the final concatenated name.

────────────────────────────────────────
ATTRIBUTE CAPTURE WINDOW (CRITICAL):
────────────────────────────────────────

- After detecting a product_name, scan ONLY the contiguous block of lines
  immediately following it.
- Stop scanning when:
  a) a new product_name is encountered, OR
  b) a clear section break is reached (e.g. blank line, page break, heading).
- Only attributes found inside this block may be assigned to the product.

ATTRIBUTE EXTRACTION RULES:
- Map common label variants to the correct attribute
  (e.g., "Style #", "SKU" → style_number; "WSP", "Wholesale" → ws_price).
- Preserve values exactly as written (except trimming whitespace).
- Do NOT normalize units, prices, or text.
- If multiple values for the same attribute appear in the block,
  use the first occurrence.
- Merchant name might be on an image in the header or footer. 
- If attribute labels appear without explicit keys (e.g., bare prices),
  associate them ONLY if they appear directly below the product_name
  and before any other product_name.

────────────────────────────────────────
DUPLICATION RULE:
────────────────────────────────────────

- If the same product_name appears multiple times, extract each occurrence
  as a separate product entry.
- Do NOT merge or deduplicate products.
